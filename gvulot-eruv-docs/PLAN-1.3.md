# תכנון 1.3.0: מצב מנותק לפי הגדרת אוצריא, הגדרת קישורים, הורדת חוברת שלמה

נכתב ב-27.10.2026 לפני תחילת העבודה. בסיס: 1.2.1 (main). כל שלב נשמר ב-commit נפרד. ✅ = נעשה ונדחף.

## 1. מצב מנותק לפי הגדרת אוצריא — issue #2
- **היום (1.2.1):** `setOnline` מקבל `connectivity.isOnline` (= `!isOfflineMode && hasNetwork`). כלומר מי שפשוט בלי רשת כרגע
  מאבד את כל הקישורים, אף שהוא רוצה להעתיק קישור ולפתוח אותו אחר כך.
- **מעכשיו:** ההסתרה נקבעת **רק** לפי `isOfflineMode` (המשתמש סימן "ללא גישה לאינטרנט" בהגדרות אוצריא):
  - באתחול: `payload.connectivity.isOfflineMode`; אם חסר/`null` — `app.getConnectivity` (בלי `forceRefresh`, אין צורך בבדיקת רשת).
  - עדכון חי: אוצריא לא שולחת אירוע ייעודי לקישוריות. לפי ה-SDK (`docs/plugin-sdk/API_REFERENCE.md`, `app.getConnectivity`:
    "isOfflineMode נקרא מחדש בכל קריאה") — מאזינים ל-`settings.changed` (הרשאה חדשה `events.subscribe:settings.changed`)
    ובכל שינוי הגדרה קוראים שוב ל-`app.getConnectivity`. נשאר גם הבידוק ב-focus וב-`plugin.resumed`.
  - שם השדה במצב: `state.offline` (במקום `state.online`), כדי שלא יתבלבל עם רשת בפועל. `map-ui` ממשיך לקבל `online: !state.offline`.

## 2. הגדרה: "קישור חיצוני — פתיחה בדפדפן / העתקה" — issue #2
- בחלון "אודות" (ליד המתג של סרגל העיון) בחירה בין שתי אפשרויות, נשמרת ב-`storage` במפתח `linkMode` (`open` ברירת מחדל / `copy`).
- `open`: **המנגנון הקיים נשמר** — `confirmExternal` (‏`ui.showConfirm`) ואז `app.openUrl` (הרשאה `app.open_url`, כבר קיימת;
  minAppVersion 0.9.98 ≥ 0.9.95). הקישור גם מועתק ללוח כמו היום.
- `copy`: בלי חלון אישור ובלי פתיחה — רק העתקה ללוח והודעה "הקישור הועתק". אם ההעתקה נכשלת — מציגים את הכתובת בהודעה.
- לפי ההנחיה בדיווח: לכידת לחיצות על `<a href="http…">` בשלב capture, `preventDefault`, ומעבר דרך `openLink` — כדי שאף קישור
  (גם עתידי, גם בתוכן שנבנה מנתונים) לא ינסה לנווט בתוך ה-iframe ולא ייפתח ב-`target=_blank`. ה-fallback של `window.open` נשאר
  רק מחוץ לאוצריא (בדיקה בדפדפן).

## 3. הורדת חוברת שלמה בלחיצה אחת — issue #3
- **היום:** בתפריט הייצוא של המציג — PNG/JPG/הדפסה של **עמוד אחד**.
- **מעכשיו**, כשחוברת פתוחה במציג (V.doc), בתפריט הייצוא נוספים:
  - **החוברת כולה כ-PDF** — קובץ אחד.
  - **החוברת כולה כ-ZIP** (תמונות JPG, עמוד בקובץ).
  - כשנפתח רק חלק (`V.range`, למשל חלק ב' של דרך התחומין בדף מודיעין עילית) — גם "**החלק הזה בלבד**" (PDF).
- **מימוש בלי ספריות חיצוניות** (אין CDN באוצריא):
  - כל עמוד מצויר ב-pdf.js (הקיים) לרוחב 1400px, ומעליו **פס הכותרת של הייצוא** (`exportLinks` — קישור GitHub והפניה לחנות אוצריא,
    כנדרש בכל ייצוא), ונשמר כ-JPEG.
  - PDF: כותב PDF מינימלי (גרסה 1.4) — אובייקט `Image` עם `DCTDecode` לכל עמוד, עמוד בגודל התמונה. בלי דחיסה נוספת.
  - ZIP: שיטת STORE (בלי דחיסה — JPEG כבר דחוס) עם CRC32 ושמות קבצים ב-UTF-8 (דגל 0x800). `עמוד-001.jpg`…, ובנוסף `קרא-אותי.txt`
    עם המקור, האזהרה וקישורי ההורדה של התוסף.
  - שמירה: `fs.beginBinaryWrite` + PUT + `fs.commitUserFileWrite` (כמו `exportImage`) — חלון "שמירה בשם" אחד לכל הקובץ.
  - התקדמות בהודעה ("מכין עמוד 12 מתוך 93"); אין הרצה במקביל של שתי הורדות. העמודים לא נשמרים במטמון של המציג (זיכרון).
- גודל משוער: עמוד ≈ 150–250KB → חוברת של 93 עמודים ≈ 15–20MB. מחוץ לאוצריא — הורדה ישירה בדפדפן לבדיקה.
